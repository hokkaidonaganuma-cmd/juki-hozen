# 重機保全台帳（Supabase接続版）

管理番号ごとの重機を登録し、整備記録を積み重ねる台帳アプリ。
Supabase（Postgres + 認証）をバックエンドにしているため、**同じログイン情報でどの端末（iOS / Android / PC）からでもログインでき、同じデータが見えます。**

設計の詳細は、このプロジェクトと一緒に渡された `juki-hozen-backend-plan.md` を参照してください。

---

## 1. Supabase プロジェクトを作成する

1. [supabase.com](https://supabase.com) で無料アカウントを作成し、新規プロジェクトを作成する。
2. プロジェクト作成後、左メニューの **SQL Editor** を開き、このプロジェクト内の `supabase/schema.sql` の中身を貼り付けて実行する。
   - `machines` `maintenance_records` `master_options` `master_content` `profiles` の各テーブルと、Row Level Security（自分のデータしか見えない設定）が作成されます。
3. 左メニューの **Authentication → Providers** で「Email」が有効になっていることを確認する（デフォルトで有効なはずです）。
4. **Authentication → URL Configuration** で、以下を設定する（開発中は localhost、本番は実際に公開するドメインに置き換えてください）。
   - Site URL: `http://localhost:5173`（本番デプロイ後は公開URLに変更）
   - Redirect URLs に `http://localhost:5173/reset-password` と、本番URLの `/reset-password` を追加
5. **Project Settings → API** から、`Project URL` と `anon public` キーをコピーする（次の手順で使います）。

## 2. ローカルで動かす

```bash
npm install
cp .env.example .env
# .env を開いて、手順1でコピーした URL と anon key を貼り付ける

npm run dev
```

`http://localhost:5173` を開くと、ログイン画面が表示されます。
「初めての方はこちら（新規登録）」からメールアドレスとパスワードでアカウントを作成すると、そのままログインできます。

## 3. 本番公開（Vercel の例）

```bash
npm run build
```

もしくは GitHub にプッシュして [vercel.com](https://vercel.com) でリポジトリをインポートするだけでもデプロイできます。

デプロイ時、Vercel のプロジェクト設定 → Environment Variables に、`.env` と同じ内容
（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）を追加してください。

デプロイ後に発行される公開URL（例：`https://juki-hozen.vercel.app`）を、
Supabase の **Authentication → URL Configuration** の Site URL / Redirect URLs にも追加するのを忘れないでください
（これを忘れると、パスワード再設定メールのリンクが正しく機能しません）。

## 4. 複数端末で使う

デプロイ後の公開URLに、iPhone・Android・PCのどのブラウザからアクセスしても、
同じメールアドレス・パスワードでログインすれば同じデータが見えます。
スマホでは「ホーム画面に追加」をしておくと、アプリのようにアイコンから起動できます。

## 5. 追加された機能

- **整備履歴の編集**：機械の詳細画面で、各整備記録の右上にある「編集」ボタンから内容を修正できます。
- **登録済み機械の削除**：「⚙ マスタ編集」ページに「登録済み機械の削除」カードがあります。削除すると、その機械の整備記録もあわせて削除されます（データベース側の `ON DELETE CASCADE` により自動的に処理されます）。
- **メーカーごとのグループ表示**：一覧画面はメーカーごとに見出しを立てて表示されます。管理番号・機種・メーカーの絞り込みと組み合わせて使えます。
- **車台番号**：機械登録フォームに追加。詳細画面にも表示されます。
- **写真の登録**：機械登録時・整備記録の追加/編集時に写真を1枚添付できます。Supabase Storage の `machine-photos` バケット（公開バケット）に保存され、一覧画面では管理番号の横に小さいサムネイルとして表示されます。
- 既存のSupabaseプロジェクトに対しては、`supabase/schema.sql` を もう一度そのまま実行すれば、新しいカラム（`chassis_no` / `photo_url`）とストレージバケットが安全に追加されます（`IF NOT EXISTS` 系の記述のみで構成されています）。

## トラブルシューティング

### 「Bucket not found」エラーが出る場合

写真アップロード用のバケット名は **`machine-photos`** 固定です（`src/api.js` のコードが直接この名前を参照しています）。このエラーは、Supabaseプロジェクト側にこのバケットがまだ存在しないことが原因です。以下のどちらかの方法で作成してください。

**方法A：ダッシュボードから作成（最も確実）**
1. Supabaseダッシュボード → 左メニューの **Storage** を開く
2. **New bucket** をクリック
3. Name に `machine-photos` と入力（大文字小文字・ハイフンも正確に）
4. **Public bucket** を ON にする（写真をアプリ上で表示するために必要）
5. **Create bucket** で作成
6. 続けて、SQL Editor で `supabase/schema.sql` の一番下にある「Storage」セクション（`create policy "machine-photos: ...` から始まる4つのポリシー文）を実行する（すでにバケットがある状態なら `insert into storage.buckets` の行はそのまま実行しても無害です）

**方法B：SQL Editorから作成**
1. SQL Editor で `supabase/schema.sql` を最初からもう一度実行する
2. 最新版の `schema.sql` はバケット作成・ポリシー作成のどちらも再実行できるように更新済みです（`on conflict` と `drop policy if exists` を使用）。以前のバージョンのファイルで一度実行済みの場合は「policy already exists」エラーで途中停止することがあるため、その場合はこの最新の `schema.sql` に差し替えてから再実行してください。

作成後、ブラウザをリロードしてから写真アップロードを再度お試しください。

## 既知の制約・今後の拡張余地

- 現状は1ユーザー＝1台帳（`owner_id` で分離）です。会社やチームで台帳を共有したい場合は、
  `organizations` テーブルを追加して `machines.owner_id` の代わりに `organization_id` で紐付ける設計に拡張してください。
- ネイティブのiOS/Androidアプリ（App Store / Google Play配信）にしたい場合は、
  このWebアプリをベースに [Capacitor](https://capacitorjs.com/) でラップする追加作業が必要です。
  まずはWeb版で複数端末対応ができているか確認してから検討することをおすすめします。

## 追加された機能（第3弾）

- **機械情報の編集**：詳細画面上部の「機械情報を編集」から、管理番号を含む全項目・写真を後から修正できます。
- **点検周期のデフォルトを365日に変更**：新規機械登録時の「点検周期（日）」初期値が365日になりました。次回点検予定日は「最終整備日＋点検周期（日）」で自動計算されます。
- **ステータス判定を特定自主検査基準に変更**：次回特定自主検査予定日の1か月前から「点検間近」、期限を過ぎると「要点検」になります（以前の「次回点検予定日」基準から変更）。
- **点検内容をその場で確認**：一覧の「点検間近」「要点検」の行にある「点検内容を見る」を押すと、その場で次回検査予定日・直近の整備内容を展開表示できます（詳細画面に移動しなくても内容が分かります）。
- **一覧を要点検・点検間近のみに変更**：一覧はメーカー別グループ表示をやめ、「要点検」→「点検間近」の優先順位のみを表示するようにしました（良好・未点検の機械はここには出ません）。
- **見出し下の説明文を削除**：「管理番号で機械を登録し…」の一文を非表示にしました。
- **会社ロゴ・ヘッダー画像・背景画像のアップロード**：「⚙ マスタ編集」→「表示設定」から、ヘッダー左上の印マークを会社ロゴに、ヘッダー背景・アプリ全体の背景を任意の画像に差し替えられます。設定は `profiles` テーブルに保存され、ログインしているアカウントに紐づきます。

## 追加された機能（第4弾）

- **メンテナンス履歴の検索**：一覧画面の上部に検索ボックスを追加しました。管理番号・機種・メーカー・型式で検索すると、ステータス（良好・点検間近・要点検・未点検）に関わらずすべての機械が候補に出てきます。候補をクリックすると、その機械の詳細画面（整備履歴）に直接移動します。一覧そのものは引き続き「要点検・点検間近」のみの表示ですが、この検索を使えばどの機械の履歴でも確認できます。
- **台帳の名称を表示設定から変更可能に**：「⚙ マスタ編集」→「表示設定」に「台帳の名称」欄を追加しました。ヘッダーの見出し（デフォルト「重機保全台帳」）を、会社名や好きな名称に変更できます。ログイン画面の見出しは、ログイン前でどのアカウントの設定か分からないため、これまで通り「重機保全台帳」のままです。

## 追加された機能（第5弾）

- **メーカー別クイック検索ボタン**：「メンテナンス履歴を見る機械を検索」の下に、ヤンマー・日立・CAT・コマツ・諸岡・その他のボタンを追加しました。押すと、そのメーカーに該当する自社機械の一覧（ステータスに関わらず）がその場に表示され、クリックすると詳細画面に移動します。「その他」は、他のボタンに登録されているメーカー名のいずれにも一致しない機械が対象になります。
- **クイック検索ボタンもマスタ編集で管理可能**：「⚙ マスタ編集」→「検索ボタン（メーカー別）」から、ボタンの追加・削除ができます。
- 既存アカウントにも、初回のクイック検索ボタン（ヤンマー・日立・CAT・コマツ・諸岡・その他）が自動的に補充されるようにしています（`schema.sql` 再実行時に1回だけ実行される移行処理）。

## 追加された変更（第6弾）

- 一覧上部にあった「管理番号：すべて」「機種：すべて」「メーカー：すべて」の絞り込みドロップダウンを削除しました（メンテナンス履歴検索・クイック検索ボタンで代替できるため）。
- 「＋ 新規機械登録」ボタンは、検索カードの右上（「メンテナンス履歴を見る機械を検索」の隣）に移動しました。
